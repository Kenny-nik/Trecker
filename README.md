# Trecker

**Trecker** — это серверная часть приложения для отслеживания привычек (habit tracker), разработанная на **Django** с использованием **Django REST Framework**.  
Проект реализует регистрацию пользователей, создание и управление привычками, а также поддержку фоновых задач через **Celery** и документирование API через **Swagger (drf-yasg)**.

---

## 🚀 Основные возможности

- 🔐 Регистрация и авторизация пользователей  
- 📆 CRUD-операции для привычек (создание, обновление, удаление, просмотр)  
- ⚙️ Валидация данных и сериализация через DRF  
- 🧩 Пагинация и фильтрация результатов  
- 🕓 Асинхронные задачи через **Celery + Redis**  
- 🌐 Поддержка CORS для фронтенд-приложений  
- 🧾 Автоматическая документация API (Swagger / Redoc)  
- 🧠 Чистая архитектура: разделение по приложениям `habit`, `users`, `config`

## Описаны модели привычек (Habits),

user — создатель привычки.

place — место, в котором необходимо выполнять привычку.

time — время, когда необходимо выполнять привычку.

act — действие, которое представляет собой привычка.

pleasant_habit — привычка, которую можно привязать к выполнению полезной привычки.

related_habit — привычка, которая связана с другой привычкой, важно указывать для полезных привычек, но не для приятных.

periodicity (по умолчанию ежедневная) — периодичность выполнения привычки для напоминания в днях.

prize — чем пользователь должен себя вознаградить после выполнения.

lead_time — время, которое предположительно потратит пользователь на выполнение привычки.

is_published — привычки можно публиковать в общий доступ, чтобы другие пользователи могли брать в пример чужие привычки.

## Описан контроллер для создания пользователя и CRUD для привычек

## Добавлена валидация
Исключён одновременный выбор связанной привычки и указания вознаграждения.

Время выполнения должно не больше 120 секунд.

В связанные привычки попадают только привычки с признаком приятной привычки.

У приятной привычки нет вознаграждения или связанной привычки.

Нельзя выполнять привычку реже, чем 1 раз в 7 дней.

## Реализована пагинация:
Для вывода списка привычек реализована пагинация с выводом по 5 привычек на страницу.

## Описаны права доступа:
Каждый пользователь имеет доступ только к своим привычкам по механизму CRUD.

Пользователь может видеть список публичных привычек без возможности их как-то редактировать или удалять.

## Реализована интеграция с Telegram
Для полноценной работы сервиса реализована работа с отложенными задачами для напоминания о том,
в какое время какие привычки необходимо выполнять через Телеграм.


## Настроена Безопасность
Настроен CORS, чтобы фронтенд мог подключаться к проекту на развернутом сервере.
